npm init создаёт файл package.json в текущей папке — это манифест твоего Node.js-проекта.

Что это за файл
package.json — «паспорт» проекта. В нём хранится:

имя и версия проекта

точка входа (main)

scripts (команды вроде npm run dev)

зависимости (dependencies, devDependencies)

метаданные (лицензия, автор, репозиторий)

настройки engines, type (commonjs / module) и т.д.

Два режима
1. Интерактивный

bash
npm init
Задаёт вопросы: name, version, description, entry point, test command, git repo, keywords, author, license. По итогу создаёт package.json.

2. Быстрый (без вопросов)

bash
npm init -y
Создаёт package.json со значениями по умолчанию. Самый частый вариант на практике.

`npm install` (кратко `npm i`) — устанавливает зависимости проекта в папку `node_modules` и синхронизирует `package-lock.json`.

## Основные варианты использования

**1. Установить всё из `package.json`**
```bash
npm install
```
Читает `dependencies` + `devDependencies` из `package.json` (или `package-lock.json`, если он есть) и ставит их. Это то, что делаешь после `git clone`.

**2. Добавить конкретный пакет**
```bash
npm install express
```
- скачивает пакет
- добавляет его в `dependencies` в `package.json`
- обновляет `package-lock.json`
- кладёт в `node_modules`

**3. Флаги, которые реально нужны**

| Команда | Что делает |
|---|---|
| `npm i express` | в `dependencies` (прод) |
| `npm i -D jest` | в `devDependencies` (только для разработки) |
| `npm i -g nodemon` | глобально (лучше избегать, ставь локально) |
| `npm i express@4.18.2` | конкретная версия |
| `npm i express@^4` | мажорная версия 4.x |
| `npm ci` | чистая установка строго по `package-lock.json` (для CI/прод) |
| `npm i --omit=dev` | только прод-зависимости |
| `npm i --no-save` | поставить, но не писать в `package.json` |

## Что происходит под капотом

1. npm читает `package.json` / `package-lock.json`
2. Строит дерево зависимостей (с учётом semver)
3. Скачивает тарболы из реестра (`registry.npmjs.org` или приватного)
4. Распаковывает в `node_modules`
5. Обновляет/создаёт `package-lock.json` — фиксирует точные версии
6. Запускает `postinstall`-скрипты пакетов, если они есть

## Важные нюансы

- **`node_modules` не коммитят.** Он в `.gitignore`. Восстанавливается через `npm install` / `npm ci`.
- **`package-lock.json` коммитят.** Он гарантирует одинаковые версии у всей команды и в CI.
- **`npm ci` vs `npm install`:**
  - `ci` — быстро, строго по lock-файлу, удаляет `node_modules` перед установкой. Для CI/деплоя.
  - `install` — может обновить версии в пределах semver. Для локальной разработки.
- **Если не ставится / странные ошибки:**
  ```bash
  rm -rf node_modules package-lock.json
  npm cache clean --force
  npm install
  ```
  (на Windows — удалить `node_modules` и `package-lock.json` вручную, потом `npm cache clean --force`)
- **Пакетный менеджер должен совпадать с lock-файлом.** Есть `pnpm-lock.yaml` — используй `pnpm install`, а не `npm`.

## Semver-префиксы (частая путаница)

```json
"express": "^4.18.2"  // 4.x.x, но не 5.0.0 (можно минорные и патчи)
"express": "~4.18.2"  // 4.18.x (только патчи)
"express": "4.18.2"   // ровно эта версия
"express": "*"        // любая (плохо)
```

Если скинешь `package.json` или текст ошибки при установке — разберём конкретно.

`nodemon` — это **утилита для разработки на Node.js, которая автоматически перезапускает твоё приложение при изменении файлов в проекте**.

Расшифровывается как **"node monitor"**.

## Простыми словами

Ты пишешь код, сохраняешь файл — `nodemon` видит изменение и сам перезапускает сервер. Не надо вручную останавливать (`Ctrl+C`) и снова запускать `node app.js`.

**Без nodemon:**
```
правишь код → Ctrl+C → node app.js → проверяешь → правишь → Ctrl+C → node app.js ...
```

**С nodemon:**
```
правишь код → сохраняешь → сервер сам перезапустился → проверяешь → ...
```

## Что конкретно делает

1. Запускает твой Node.js-файл как обычный `node`
2. Следит за файлами в проекте (по умолчанию `.js`, `.mjs`, `.cjs`, `.json`)
3. Игнорирует `node_modules` и `.git`
4. При сохранении любого отслеживаемого файла — убивает старый процесс и запускает новый
5. Показывает в консоли, что перезапустился

## Установка и запуск

```bash
npm i -D nodemon      # ставим в devDependencies
npx nodemon app.js    # запускаем
```

Обычно прописывают в `package.json`:
```json
"scripts": {
  "dev": "nodemon app.js"
}
```
и запускают:
```bash
npm run dev
```

## Важно понимать

- **Это только для разработки.** В проде запускают обычный `node` (или PM2, Docker, systemd). Nodemon туда не ставят.
- **Это не сборщик и не транспайлер.** Он просто перезапускает процесс. TS он сам не компилирует — нужен `ts-node`/`tsx` через флаг `--exec`.
- **Есть встроенная альтернатива** в самом Node.js (с 18.11+, стабильно в 20+):
  ```bash
  node --watch app.js
  ```
  Для простых случаев nodemon уже не обязателен.

## Аналогия

Это как «живой перезапуск» сервера. Представь, что ты дежуришь у выключателя и каждый раз, когда меняешь код, кто-то жмёт «перезагрузить». Nodemon — этот кто-то.

Если нужен пример под твой проект (Express, TS, NestJS) — скажи, накидаю готовую конфигурацию.
